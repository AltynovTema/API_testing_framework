Чек-лист

Обозначение статусов:
    🙈   — Not run (тест ещё не запускался);
    🧠   — In Progress (тест ещё не пройден / находится в работе);
    ✅   — Passed (тест успешно пройден);
    ❌   — Failed (тест провален).

Формат идентификатора проверки:
    <РАЗДЕЛ>-<МЕТОД>-<ТИП>-<НОМЕР>
    где РАЗДЕЛ — буква раздела (А…П),
        МЕТОД  — HTTP-метод эндпойнта (GET/POST/PATCH/PUT/DELETE),
        ТИП    — POS (позитивная) или NEG (негативная),
        НОМЕР  — порядковый номер проверки внутри группы.


Общие предусловия (универсальны для всех тестов на все методы):
    1. База данных содержит минимальный тестовый набор данных (сид-данные),
       достаточный для smoke-проверок схем MovieResponse, FindAllMoviesResponse,
       FindOneMovieResponse, MovieReviewResponse, GenreResponse:
       - минимум 3 жанра, включая genreId=1 (дефолт genreId в GET /movies);
       - минимум 11 фильмов (чтобы при дефолтном pageSize=10 был pageCount >= 2);
       - минимум по одному фильму MSK и SPB, published=true и published=false;
       - минимум один фильм с не-ASCII name (кириллица) и один с эмодзи;
       - минимум один фильм без отзывов (reviews = []) и один с отзывами;
       - id всех сущностей известны из сида.
    2. Известны тестовые учётные записи для ролей PUBLIC, USER, ADMIN, SUPER_ADMIN;
       для USER известен userId из сида.
    3. Известен id заведомо несуществующего фильма, жанра и отзыва.
    4. Сид-данные загружаются перед прогоном и очищаются после (fixture / teardown).


Раздел "Фильмы":

А) Получение афиш фильмов:
Описание:
    Метод: "GET"
    Эндпойнт: "/movies"
    Роль: "PUBLIC"

Позитивные проверки:
    A-GET-POS-01. [✅] (Вид: smoke/regression) Проверка структуры ответа относительно схемы FindAllMoviesResponse:
        Шаг 1. Отправить запрос без параметров;
        Шаг 2. Проверить статус-код 200;
        Шаг 3. Проверить что тело ответа содержит поля movies, count, page, pageSize, pageCount;
        Шаг 4. Проверить что каждый элемент movies содержит обязательные поля id, name, price,
               description, imageUrl, location, published, genreId, genre, createdAt, rating;
        Шаг 5. Проверить что location ∈ {MSK, SPB}, rating ∈ [0; 5], genre содержит name,
               movies — массив.

    A-GET-POS-02. [🙈] (Вид: smoke) Проверка устойчивости контракта при валидных параметрах:
        Шаг 1. Отправить запрос со случайными валидными значениями параметров;
        Шаг 2. Проверить статус-код 200 и соответствие тела схеме FindAllMoviesResponse.

    A-GET-POS-03. [🙈] (Вид: smoke) Проверка кодировки поля movies[].name (не-ASCII):
        Шаг 1. Отправить GET /movies с фильтром, гарантированно включающим фильм
               с кириллическим name и фильм с эмодзи в name;
        Шаг 2. Проверить статус-код 200 и что movies[].name совпадает с эталоном
               из сида побайтово (UTF-8, emoji как codepoints).

Негативные проверки:
    A-GET-NEG-01. [🙈] (Вид: smoke) Проверка невалидных типов значений параметров:
        Шаг 1. Установить pageSize=abc, отправить запрос;
        Шаг 2. Проверить статус-код 400.

    A-GET-NEG-02. [🙈] (Вид: smoke) Проверка невалидных значений enum-полей:
        Шаг 1. Установить locations=ABC, отправить запрос;
        Шаг 2. Проверить статус-код 400.
